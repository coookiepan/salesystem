# 長官儀表板 — MVP Prototype

> **這不是產品，是拿來吵架的道具。**
> 目的是在寫進 `index.html` 之前，先用可點的畫面確認資訊架構、使用流程、頁面層級、操作方式、
> 以及各種狀態與 Edge Case。確認完之後這個資料夾就可以刪掉。

## 怎麼開

用瀏覽器直接打開 [`boss-dashboard.html`](boss-dashboard.html)，不需要 server、不需要安裝任何東西。

- 唯一的外部依賴是 Leaflet（與主系統同一組 unpkg CDN＋SRI）。**離線開啟時地圖會顯示
  「地圖元件未能載入」，其餘功能完全正常**——這本身就是要驗證的 Edge Case 之一。
- 資料全部是 Mock，寫死在檔案裡：無後端、無資料庫、無登入、不寫 localStorage。
- 「今天」固定為 **2026-08-16**，亂數是 seeded 的，所以**每次開啟看到的數字完全一樣**，
  方便反覆對照討論。

## 畫面下方那條「模擬狀態」列

Prototype 專用（正式版不會有）。用它切換六種資料情境，這是這份原型最重要的部分：

| 按鈕 | 模擬什麼 | 要驗證的事 |
|------|---------|-----------|
| 正常 | 5 位業務、78 家客戶 | 主要流程 |
| 載入中 | 向各業務雲端取數中 | 用骨架而非轉圈圈，版面不跳動 |
| 首次使用（無來源） | 尚未設定任何業務資料表 | 空狀態要能引導設定，不是一片空白 |
| 部分業務失敗 | 1 位業務的 Sheet 抓不到 | **其餘業務照常顯示**，錯誤明確歸屬到那個人 |
| 資料過期 | 快照是 66 小時前 | 數字不能假裝是即時的 |
| 全所皆新人 | 有業務、零客戶 | 零資料不等於壞掉 |

右上角還可切換 深/淺色（自動 → 淺色 → 深色）。

## 頁面層級

```
L1  總覽（單一捲動頁）
     資料狀態列 → KPI×5 → ⚠需要關注 → 全所漏斗 → 業務員 → 地區分佈
L2  視角切換（同頁，非換頁）
     客戶清單（多重篩選＋排序） / 地圖（Leaflet 點位＋同步清單）
L3  客戶詳情 Drawer（右側滑出，蓋在任何視角上，不失去上下文）
```

**核心設計主張：每一個數字都能點開看到組成。** KPI「試用中 29 家」點下去就是已套用
「狀態＝試用盤」的客戶清單；業務卡、地區長條同理。數字不能被下鑽的儀表板，長官看兩次就不看了。

## ⚠ 需要關注 — 這是產品的靈魂

長官不需要另一張月報表，他需要「今天該找誰」。四條規則（可在程式碼 `RULES` 一處改）：

| 嚴重度 | 規則 | 條件 |
|--------|------|------|
| 🔴 1 | 試用停滯 | 試用中且投放超過 30 天仍未報價 |
| 🟠 2 | 將成約逾期 | 停在「將成約」且超過 14 天無新拜訪 |
| 🔵 3 | 高金額案 | 試用 4W 金額 ≥ $10,000 |
| ⚪ 4 | 久未拜訪 | 開發中且超過 21 天未拜訪 |

目前 Mock 資料下命中 **17 / 78 家（約 22%）**，清單只顯示前 10 筆。
**這個比例是需要一起校準的重點**：命中率太高，警示就變成背景雜訊，長官會直接略過。

## Mock 資料是刻意設計的，不是隨機的

兩個地方特意**不交給機率**，因為 prototype 的價值在於「每一種狀態都要看得到」：

- **狀態走精確配額**（`STATUS_MIX` + `quota()`）：n≈20 時純亂數抽樣常讓罕見狀態
  （已轉交 4%、拒絕 5%）整段抽空，demo 就少掉要驗證的畫面。
- **未定位客戶固定約 12%**：地圖的「另有 N 家沒有座標」必須每次都能被驗證。

另外植入了 8 筆手工 Edge Case：試用 64 天的高金額停滯案、卡住的將成約、
**試用中但沒登記品項**（金額顯示「未登記品項」而非誤導性的 `$0`）、
超長店名、同名重複建檔、無座標客戶。

## 與主系統的對齊

刻意沿用 `index.html` 的既有定義，之後要接回去才不用重畫：

- **九階段狀態** `STATUS` 與 `SS_STYLE` 色票
- **金額口徑**：更換週期 1W/2W/4W → 每 4 週換 4/2/1 次；4W 金額＝契約單價 × 次數 × 數量
- **試用盤定義**：試用中／報價／將成約（與 `?admin=1` 的 `STATUS_TRIAL_SET` 一致）
- **設計 tokens**：色票取自 `tokens.css`（為維持單檔而內嵌），顏色一律走 CSS 變數，深色模式自動生效

## 已知限制（原型階段刻意不做）

- 沒有時間趨勢／月度目標達成率——需要歷史快照，現行資料模型只有當下狀態
- 沒有登入與權限，任何人開啟都看得到全部資料
- 客戶清單 78 列一次渲染，沒有分頁或虛擬捲動
- 地圖在無網路時不可用（清單與地區分佈仍可用）

## 下一步要一起決定的事

1. **關注規則的門檻**（30/14/21 天、$10,000）是否符合實際帶人節奏？22% 的命中率會不會太吵？
2. 業務員卡要不要顯示**排名**？（會影響管理氣氛，是產品個性決定，不是技術決定）
3. 長官需不需要在儀表板上**留言／指派**給業務？還是維持唯讀、溝通走 LINE？
4. 這個儀表板是併入 `index.html` 的 `?admin=1`，還是像 `home.html` 那樣獨立成一個檔？
